# 운동 기록 앱 계획서

2026-09-28 작성, 이후 계속 갱신

## 개요

운동 플랜, 실제 수행 기록, 추천 무게, 다음 주 플랜을 한 앱에서 보고 관리한다. 지금은 플랜 텍스트, 메모 앱의 기록, AI 채팅의 추천 무게와 다음 주 플랜을 따로 오가야 해서 번거롭다.

1주차는 나 혼자 쓰는 앱으로 완성하고, 2주차에 다른 사용자도 **로그인만으로** 쓸 수 있게 연다. AI가 필요할 때는 **규칙 파서를 먼저** 쓰고, 파서로 못 풀면 **서버에 있는 운영자 Gemini 키**(`GEMINI_API_KEY`)로 처리한다. 초대 사용자에게 **자기 Gemini 키 연동은 요구하지 않는다**(나중에 선택 기능으로 검토). 입력은 텍스트(TXT) 붙여넣기 하나로 통일하고, CSV와 트레이너용 기능은 나중에 본다. 장기적으로는 크로스핏·웨이트뿐 아니라 러닝, 사이클, 수영 등 여러 운동을 기록하는 사람이 쓸 수 있는 앱을 목표로 한다.

## 핵심 흐름

앱의 중심은 플랜(해야 할 것)과 수행(실제로 한 것)을 한 화면에 붙이는 것이다.

1. **플랜 붙여넣기**: 플랜 텍스트를 붙여넣으면 AI가 날짜·파트·동작·횟수·무게·템포로 나눠 요일별로 저장한다. 주 1회.
2. **오늘 화면**: 오늘 플랜 옆에 내 추천 무게를 보여준다. 추천 무게는 규칙으로 계산한다(아래 "추천 무게 규칙").
3. **기록**: 탭으로 고치거나 메모를 붙여넣는다. 메모는 규칙 파서가 먼저 처리하고, 해석 못 한 줄만 AI로 보낸다.
4. **기록·추이**: 종목별 기록 목록과 최고 기록 그래프 1개.
5. **다음 주 플랜 생성**: 블록 일정, 지난 플랜 원문, 이번 주 기록을 넣어 AI가 1번과 같은 텍스트 형식으로 만든다. 결과는 1번 파서로 다시 저장하고, 텍스트로 복사해 공유할 수 있다.

5번이 1번과 같은 텍스트 형식을 내놓기 때문에 코치가 쓴 플랜이든 AI가 만든 플랜이든 같은 입구로 들어온다.

## 추천 무게 규칙

- 기준값: % 표기면 1RM × %, 무게 표기면 표기 무게 × 개인 비율
- 증량 조건: 지난주 같은 종목 기록보다 무거워야 한다. 기준값이 지난주 기록 이하면 지난주 기록 + 최소 증량 단위로 올린다
- 반복 수가 지난주와 다르면 추정 1RM으로 환산해 비교한다
- 예외: 디로드·테스트 주, 지난주 처방 반복 수를 못 채운 종목은 유지
- 1RM을 넘지 않고, 원판 단위로 반올림한다. 반복 수는 조정하지 않는다

## 표기 규칙: 공통과 개인 나누기 (2주차 기획 때 확정)

표기 규칙은 3단계로 나눈다. 우선순위는 개인 사전 > 프리셋 > 공통.


| 단계     | 내용                       | 예시                                                 |
| ------ | ------------------------ | -------------------------------------------------- |
| 공통 코어  | 누구에게나 통하는 형식             | kg/lb/#/파운드/키로, 5x5, 5세트 5회, 5/5/5, @30X1, %, 1:30 |
| 종목 사전  | 정규 종목 + 여러 언어 별칭 + 오타 허용 | FS = 프론트스쿼트 = 프스 = front squat, SANTCH → snatch    |
| 개인 프리셋 | 특정 사람·박스만의 규칙            | 내 박스(ataraxia) 표기, 플랜 무게는 최상위자 기준                  |


내 박스 규칙 중 공통으로 옮길 후보 (초안):

- **공통 후보**: A1/A2 슈퍼세트, @템포와 X, 숫자 나열 세트, N X M, EMOM과 번갈아 표기(1-/2-, ODD/EVEN), AMRAP, FOR TIME(CAP), EVERY N:NN, REST B/T, ON/OFF, RIGHT INTO, BUY IN/CASH OUT, 21-15-9, 10 DOWN TO 1, BUILD, HEAVY SINGLE, UNTIL FAIL, 단위(#, lb, kg, 인치), 널리 쓰는 종목 약어(FS, BS, DL, PC, PJ, TTB, DU, WB 등)
- **개인 유지**: "1, 1"의 해석, AMRAP -2, REST 1:1, PARTNER 1:1, SAME TIME, 플랜 무게를 최상위자 기준으로 보는 규칙, 박스 고유 약어(F R B S U, B.K/A.K 등), 알려진 오타(LANDMIND, DB SKULL CLUSTER)
- **판단 기준**: 다른 박스·앱에서도 같은 뜻으로 쓰이면 공통, 뜻이 갈리거나 우리 박스에서만 쓰면 개인. 애매하면 개인에 두고, 여러 사용자가 같은 뜻으로 등록하면 공통으로 올린다.



## 모든 운동으로 넓히기 위해 미리 고려할 것

- **측정 방식이 다양하다**: 무게×횟수(스쿼트), 횟수만(풀업), 시간(플랭크), 거리+시간(러닝 5km 27:30), 칼로리(로잉), 높이(박스 점프), 라운드+횟수(AMRAP 점수). 세트 기록은 여러 측정값 중 필요한 것만 채우는 구조로 1주차부터 만든다.
- **체중 기반 무게**: 웨이티드 풀업(+20kg), 밴드 보조. "추가 무게"와 "보조"를 구분한다.
- **한쪽씩 하는 동작**: 8 REPS / LEG, 6 REPS / ARM. 좌우 구분 값을 둔다.
- **단위와 언어**: kg/lb, km/mi/m, 한국어·영어 종목명. 원래 단위를 보존하고 환산값을 따로 저장한다.
- **추천 규칙이 운동마다 다르다**: 무게 증량은 근력 운동에만. 러닝은 페이스·거리, 체조는 횟수 증가로 별도 규칙이 필요하다(2주차 이후).
- **기록 공개 범위**: 운동 기록과 체중은 민감할 수 있어 기본은 비공개. 공유는 사용자가 켜는 방식.
- **입력 실패를 학습 데이터로**: 사용자가 파싱 결과를 고친 기록이 쌓이면 공통 사전과 프롬프트를 개선하는 근거가 된다.



## 기술 스택과 설계 원칙

Next.js + TypeScript + Tailwind + shadcn/ui, Vercel 배포, Supabase(DB·인증), Drizzle ORM, Vitest. AI는 Gemini 무료 티어. 세부 원칙은 `CLAUDE.md` 참고.

규칙 파서는 조각 나누기 → 조각별 의미 붙이기 → 세트 조합의 세 단계 순수 함수로 짜고, 입력·기대 결과 테스트 20~30개를 먼저 쓴다. 이 파서는 직접 짠다.

**키 (1·2주차 공통)**  

- **운영 키 하나**: 서버 `GEMINI_API_KEY`만 사용. 클라이언트·DB·로그에 키를 두지 않는다.  
- **2주차 초대 사용자**: 자기 키 **불필요**. 모든 AI는 위 운영 키로 서버에서만 호출.  
- **온보딩 고지**: (1) 입력 일부가 Google Gemini로 전송됨, (2) 무료 티어는 Google 제품 개선에 쓰일 수 있음, (3) 운영자 API 할당량·일일 제한이 있을 수 있음.  
- **선택 기능(미래)**: BYOK·유료 API는 트래픽 보며 추가. 2주차 범위 아님.



## AI 개발 도구 운영

- 흐름: researcher 조사 → planner 계획 → 사용자 승인 → 메인 에이전트 구현 → reviewer 검토 → 사용자 확인 후 커밋 (`.cursor/rules/workflow.mdc`)
- 위험 명령과 DB 변경은 훅이 실행 전에 확인을 받고, `.env*` 읽기는 훅이 막는다
- 원본 로그는 `.ai-logs/raw/`(gitignore)에 쌓이고, 공개용은 `scripts/sanitize-logs.mjs`로 민감 정보를 지운 뒤 `ai-logs/`에 만든다. **pre-commit**에서 sanitize·`ai-logs/` 스테이징·`tsc`·`next build`를 실행한다
- 매주 일요일 로그를 보고 CLAUDE.md, 규칙, 서브에이전트 지시를 고친다
